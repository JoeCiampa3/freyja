# CONVENTIONS

Rules that outlive any tool in this repo. Tools get replaced; these do not. If code and this file disagree, one of them is wrong: fix it deliberately, never let it drift. Owner: Joe. Claude Code may propose edits here, but a schema change and its edit to this file land in the same commit.

## 1. Principles

**One home per quantity.** Anthropometric inputs, segment inertial data, joint centres and ROM live in the Freyja Anthropometric Reference sheet. Everything else is derived from them by code, or lives in exactly one authored file. A hand-typed copy of a value that exists elsewhere is a bug, even when it is currently correct.

**Authored or generated, never both.** Every file is one or the other. Generated files carry a banner (section 4), are never edited by hand, and are byte-reproducible from their inputs.

**Downstream reads the snapshot, not the sheet.** `pre_processor` is the only code that reads the live sheet. Checks, sim runs, the CAD bridge and reports read `params/snapshot.csv`. Any result is then reproducible from a commit.

**Provenance.** Every number entering the sheet or an authored file has a citation, or a script path that reproduces it. No circular validation: a model is never validated against the data it was built from.

**Staleness is a hash mismatch.** Every generated artifact records the hash of its inputs. A mismatch means stale, and tools say so instead of guessing.

**Checks are executable and can fail.** A claim of correctness is a named check. Every check has a mutation test proving it fails when the thing it guards is broken. Known deviations are recorded as explicit waivers (section 7), never as a quiet INFO.

**Determinism.** Build artifacts carry no timestamps or absolute paths. Time lives in the log, not in artifacts. Same inputs, byte-identical output. A run record is an event, not a build artifact: its `run_id` encodes the start time and nothing else in it is time-dependent, and every metric is deterministic given the same inputs and seed.

**No secrets in the repo.** Per-machine configuration lives in `local_config.json` (gitignored) or environment variables. The service-account key stays outside the working tree.

## 3. Identifiers

IDs are the join key across every artifact. Segments are lowercase letters, digits, underscore and hyphen, separated by dots. IDs are permanent: never reused, never deleted. A retired ID is marked superseded.

| Kind | Form | Example |
|---|---|---|
| Quantity key | existing `pre_processor` placeholder names; do not rename | `thigh_right_mass`, `hip_flexion` |
| Requirement | `req.<joint-or-subsystem>.<quantity>` | `req.ankle.df_min` |
| Decision | `adr-NNNN` | `adr-0012` |
| Part | `part.<assembly>.<name>` (revision is a field, not part of the ID) | `part.hip.ach` |
| Check | `check.<area>.<name>` | `check.mjcf.joint_signs` |
| Gate | `gate.<plan id, lowercase>` | `gate.g0`, `gate.g-h` |
| Run | `run.<YYYYMMDD>-<HHMM>-<scenario>` | `run.20261012-1430-walk_1p4` |
| Design point | `dp-NNN` | `dp-003` |
| Open item | `oi-NNN` | `oi-014` |

Filenames derive from the ID. Fusion user parameters cannot contain dots, so the CAD bridge maps `.` to `_` on the Fusion side only.

## 4. Generated files

Every generated file starts with a banner naming its tool and inputs.

```
GENERATED by <tool> from <inputs> (snapshot sha256:<12 hex>). Do not edit; change the inputs and rebuild.
```

Use the file type's comment syntax. JSON has no comments, so it carries top-level `generated_by` and `inputs` keys instead. Generated output is deterministic: sorted keys, LF line endings, no timestamps.

## 5. Parameter snapshot (`params/snapshot/1`)

`params/snapshot.csv` has columns `placeholder,value,sheet_source`, sorted by `placeholder`, values formatted by the same `fmt()` as `pre_processor`. It is rewritten on every successful build and only when its content changed. History is git history; read it with `git diff`.

`params/snapshot.meta.json` holds `schema` (`params/snapshot/1`), `snapshot_sha256`, `sheet_fingerprint` (the hash from `watch.sheet_fingerprint`), `template_sha256`, `model_sha256`, and `pre_processor_commit`. It must never contain the sheet ID, any credential, or an absolute path.

The banner in `sim/models/freyja.xml` carries the first 12 hex characters of `snapshot_sha256`.

If the sheet has a `targets` named range (`'BSIP Reference'!A1:B2`: label in column A with its unit in brackets, value in column B), its rows enter the snapshot as `target_mass` (kg) and `target_stature` (m), converted to SI, with the cell as `sheet_source`. They feed checks only; templates cannot use them. Without the range the keys are absent. The snapshot, its metadata and the model are installed together or not at all, and are written with LF line endings. `build_model()` writes the snapshot only when given a `snapshot_dir`; the command line and the watcher pass `params/` when building the default output.

## 6. Run records (`run-summary/1`)

Every sim run writes `sim/runs/<id minus "run.">/summary.json`. It is small and text-only, and is the thing Claude reads. Raw timeseries go in `raw.npz` beside it and stay gitignored; `summary.json` files are tracked, as are the generated `sim/runs/DIGEST.md` and `sim/runs/ENVELOPE.md`. The schema is `docs/schemas/run-summary-1.schema.json`, which carries the definition of every field and is validated on every write. It was amended in place before any record existed; after the first committed run, any change bumps the version.

```json
{
  "schema": "run-summary/1",
  "run_id": "run.20261012-1430-walk_1p4",
  "git_commit": "<sha>", "git_dirty": false, "diff_sha256": null,
  "snapshot_sha256": "<sha>", "model_sha256": "<sha>",
  "seed": 0,
  "env": {"mujoco": "3.10.0", "python": "3.11.9", "numpy": "2.4.6"},
  "scenario": {"name": "walk_1p4", "params": {}},
  "controller": {"name": "", "version": ""},
  "timestep_s": 0.002, "duration_s": 0.0,
  "support": "ground",
  "window": {"start_s": 0.0, "end_s": 0.0},
  "outcome": "completed",
  "joints": {
    "hip_fe_right": {
      "torque_source": "applied",
      "torque_peak_nm": 0.0, "torque_rms_nm": 0.0,
      "speed_peak_rad_s": 0.0, "power_peak_w": 0.0,
      "rom_used_deg": [0.0, 0.0], "rom_limit_deg": [0.0, 0.0],
      "limit_hit_fraction": 0.0
    }
  },
  "contacts": {"foot_right": {"normal_force_peak_n": 0.0, "friction_ratio_peak": 0.0}},
  "balance": {"support_margin_min_m": 0.0},
  "checks": {"passed": [], "failed": [], "waived": []}
}
```

`outcome` is `completed`, `fell` or `diverged`. `support` is `ground` or `gantry`. `torque_source` is `applied` (ideal joint torque on `qfrc_applied` in forward dynamics, ground mode) or `inverse_dynamics` (`mj_inverse` with prescribed `qacc`, gantry mode only: with floor contacts the inverse contact force comes from the soft-constraint model, so the root rows do not close). `diff_sha256` hashes `git diff HEAD` and is null when the tracked tree is clean. Optional keys: `skipped` (joint to reason, e.g. `unlimited`) and `diagnostics` (scenario-specific named numbers). Joint torque is about the model's own hinge axes (the decoupled hip architecture); it is not actuator torque for a coupled-hip variant. Units are SI except angles in degrees, and are named in the key suffix.

## 7. Checks

Checks live in `checks/`, run under pytest (`pytest.ini` collects `tests/` and `checks/`; the old unittest suites now live in `tests/`), and tag themselves with their ID and tier:

```python
@pytest.mark.check("check.mjcf.mirror", tier="gate")
```

A **gate** check blocks installation of a new `freyja.xml`: `build_model()` runs the checks on the temporary XML through its `post_checks` hook (`pre_processor.py` and `watch.py` both pass it), and on a gate failure parks the new XML as `freyja_FAILED.xml`, leaves the last good model, snapshot and metadata in place, and prints the failing check IDs. `--no-checks` skips the hook, as does a scratch build with `--output`. Advisory results are printed and written to `checks/last_run.json` (gitignored). An **advisory** check reports and never blocks. Checks run offline, deterministically, and in seconds. Every tolerance is a named constant with its unit and its reason in a comment. Every check has a mutation test: a deliberately broken copy of the model on which the check must fail.

Known deviations are recorded in `checks/waivers.yaml`. A waived check still runs and reports as WAIVED. A waiver on a check that now passes produces a warning, as does one that names an unknown check or is past its `review_by` date. A waiver takes effect only with `confirmed: true`; Claude may propose one with `confirmed: false`, and Joe confirms it.

The machinery is `checks/checklib.py` (registry, context, waivers, `run_checks`), shared by pytest, the build gate and `fy check`; the checks are in `checks/mjcf_checks.py`. A check returns one or more results, and a result may carry its own ID (`check.mjcf.mass_closure.target` is the advisory half of `check.mjcf.mass_closure`). A check whose ID is unknown to the registry cannot be waived. `checks/joint_polarity.yaml` carries `status: DRAFT` until Joe approves it; while it is DRAFT, `check.mjcf.joint_signs` reports as advisory.

```yaml
- check: check.mjcf.com_pct_stature
  reason: Whole-body CoM at 55.26% of stature, ~0.1% below the Virmavirta & Isolehto band
  source: docs/memos/memo1b.md          # Validations section
  recorded: YYYY-MM-DD
  review_by: YYYY-MM-DD
  confirmed: true                       # false = proposed, has no effect
```

## 8. Records

**Requirement** (`requirements/<id>.yaml`):

```yaml
id: req.ankle.df_min        # illustrative
statement: <what must be true>
value: 0
unit: deg
source: <citation, or run id for sim-derived>
rationale: <why>
verified_by: [check.mjcf.rom_ankle]
status: active              # active | superseded | waived
```

**Decision** (`decisions/NNNN-slug.md`):

```markdown
---
id: adr-0012
status: accepted            # proposed | accepted | superseded-by: adr-NNNN
date: YYYY-MM-DD
links: [req.x.y, part.a.b]
---
## Context
## Decision
## Consequences
## Rejected options, and why each one died
```

The rejected-options section is the part that matters on a decade horizon.

**Notebook** (`notebook/YYYY-MM-DD-slug.md`) carries front matter `origin: me | source | claude`, plus `source:` for anything read. Notes of `claude` origin record decisions and open questions, not narrative.

## 9. Rules for Claude Code

1. Read this file first. Run `fy test` (or, until `fy` exists, the baseline commands in the current brief) before and after every change.
2. Write the test or check first, watch it fail, then implement.
3. Never hand-edit a generated file. Never touch `local_config.json`, credentials, or the sheet.
4. Do not change what `pre_processor` reads from the sheet, or the meaning of any placeholder, without asking.
5. A check that fails on the current model is a finding, not a bug to fix silently. Report the measured number and stop.
6. No new dependency without asking. No `eval`. No network access in tests.
7. One commit per task, with the evidence (test output) in the message.
